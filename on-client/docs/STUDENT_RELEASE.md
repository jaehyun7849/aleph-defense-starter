커밋은 자기 자신의 SHA를 파일 본문에 미리 넣을 수 없으므로, 최종 SHA를 추측해 적지 않습니다. 아래처럼 **이 문서를 처음 추가한 커밋**을 읽어 사용합니다. 향후 main이 움직여도 해당 SHA로 고정합니다.

```powershell
git log --diff-filter=A --format=%H -- on-client/docs/STUDENT_RELEASE.md
git rev-parse HEAD
git status --short
```

현재 릴리스에서는 첫 명령의 40자리 결과가 재현 대상입니다. HEAD와 같고 작업 폴더가 깨끗한지 확인합니다. 이 문서 추가 이후 코드가 달라졌다면 이전 실행 결과를 새 버전에 합쳐 성공으로 표시하지 말고 새 릴리스와 재현 기록을 남깁니다. GitLab·다른 저장소·다른 브랜치를 임의로 만들지 않습니다.

## 이동 가능한 새 폴더 절차

사전 준비: Windows PowerShell과 Git, 기준 Node.js **24.19.0**을 준비합니다. 이번 점검은 Node **24.22.1**로 했으며 제공 도구의 허용 주 버전은 22~24입니다. Node 24.19.0 자체의 이번 재현은 미확인입니다. 기존 Node가 25라면 실행 도구가 거절하므로 기준 환경을 담당자와 확인합니다. 새 PC에서 다른 사람의 Codex 캐시 절대 경로를 복사하지 않습니다.

프로젝트 **밖의 빈 작업 위치**에서 PowerShell을 열고 아래처럼 받습니다. `keshev-repro`가 이미 있으면 덮어쓰거나 지우지 말고 다른 새 이름을 선택합니다.

```powershell
git clone --no-checkout https://github.com/jaehyun7849/aleph-defense-starter.git keshev-repro
Set-Location -LiteralPath .\keshev-repro
git log --diff-filter=A --format=%H origin/main -- on-client/docs/STUDENT_RELEASE.md
```

위 결과가 실제 최종 40자리 커밋입니다. 과제에 제출할 값과 대조한 뒤 직접 입력합니다.

```powershell
$releaseCommit = Read-Host '과제에 제출할 40자리 커밋'
if ($releaseCommit -notmatch '^[0-9a-f]{40}$') { throw '실제 40자리 커밋을 확인하세요.' }
git checkout --detach $releaseCommit
if ($LASTEXITCODE -ne 0) { throw '지정 커밋을 받지 못했습니다.' }
git rev-parse HEAD
git status --short
Set-Location -LiteralPath .\on-client
node --version
Get-Content .\package.json
node --check .\student\extension.mjs
```

Git 최상위는 새 `keshev-repro`, 실행 위치는 그 아래 `on-client`입니다. `package.json`에 외부 npm 의존성이 없고 앱의 `package-lock.json`도 없으므로 이번 재현에서는 설치할 npm 패키지가 없었습니다. 설치·취약점 재현을 위해 의존성을 추가하거나 버전을 낮추지 않습니다. `npm test`는 현재 스크립트에 없습니다.

기본 실행:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1
```

기본 주소는 `http://127.0.0.1:5189/`입니다. 포트 충돌 시 기존 작업을 종료하지 않고 아래처럼 별도 포트를 사용합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -Port 5198
```

이때 브라우저 주소는 `http://127.0.0.1:5198/`입니다. `케셰브가 켜졌습니다`와 `서버가 응답한 것만 확인했습니다` 안내는 로컬 시작 신호이며 실제 AI·SDP 연결 완료가 아닙니다. 기본 모드에서는 `ENGINE_NOT_CONNECTED`와 패키지 `not_configured`가 나올 수 있습니다.

브라우저에서 세 메뉴를 직접 확인합니다. 보호 현황·업무 앱·보안 기록을 이동하고 제공 화면과 학생 칸을 비교합니다. 종료는 이 서버를 실행한 창의 `Ctrl+C`이며, 같은 명령으로 다시 실행합니다. 배경 실행은 제공 도구의 `-Background`를 쓰고 출력된 **본인이 시작한 node 프로세스만** 종료합니다. 배경 실행 종료를 전경 Ctrl+C 검증으로 적지 않습니다.

예제 재실행은 먼저 본인이 시작한 기본 서버를 종료한 뒤 같은 앱 폴더에서 실행합니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\tools\start-alekov.ps1 -Port 5198 -Demo
```

예제는 모의 자료입니다. `practice-user`, 기기 `unknown`, 세션 `active`, 접속 기록 1건과 지원 조치 빈 배열은 제공 예제 엔진의 결과이며 실제 계정·정책·XDR 탐지·집행 성공이 아닙니다. 실운영 설정 없이 기본/예제 모드만 사용했습니다.
