# 10단계 시험 정책 복원 절차

검증된 안전 사본의 메모 권한 파일 `src/engine-resource-grants.mjs`만 복원합니다. 다른 서비스가 함께 들어 있는 파일은 거부합니다. 나머지 설정·기기/추가 확인 규칙·다른 서비스 파일·기존 감사 이력은 덮어쓰지 않습니다. 전체 정책/DB/자료 복구나 운영 배포가 아닙니다.

안전 사본은 POLICY_PREVIEW.md의 사전 검토·별도 해시·40자리 버전 검증을 만족하고 해당 메모 권한 파일도 포함해야 합니다. 실제 안전 사본은 아직 제공되지 않았습니다. 현재 정책을 자동으로 안전 사본으로 만들지 않습니다.

시험 폴더는 운영 저장소와 분리한 로컬 복사본이어야 합니다. `.git`, `api`, `public`이 있거나 루트/대상 경로가 링크이면 거부합니다. 시험 폴더의 `.aleph-policy-trial.json`에 `{ "schema":"aleph.policy.trial.v1", "isolated":true }`를 기록합니다. 이 표시는 안전성 인증이 아니며 운영 폴더를 시험 폴더로 바꾸는 용도로 사용하면 안 됩니다.

1. 먼저 미리보기 명령을 실행합니다. 이 단계는 아무 파일도 변경하지 않습니다.

```powershell
npm run policy:restore -- --backup <검증한사본.json> --sha256 <사전해시> --version <사전버전> --trial-dir <격리시험폴더>
```

2. `restoreVersion`, `scope`, `changes`, 보존할 파일 목록을 읽습니다. 맞으면 출력된 `planSha256`을 복사해 같은 명령에 `--confirm <planSha256>`을 붙여 실행합니다. 확인값이 다르거나 확인 후 정책/사본이 변경되면 중단합니다. 변경되는 파일은 메모 권한 파일 한 개이며 원자적으로 교체합니다. 다른 서비스 규칙은 복원하지 않습니다.

3. `.aleph-policy-restores.jsonl`에는 시각·버전·변경 지문·대상 파일·시작/적용 결과만 추가합니다. 기존 감사 기록을 지우거나 되돌리지 않습니다. 실제 메모·사용자 정보·토큰·정책 원문은 기록하지 않습니다. 코드가 복원 이후의 로그인/기기 검증을 생략하는 허용을 추가하지 않습니다.

4. `node --test test/policy-restore.test.mjs`로 손상시킨 가상 시험 정책에서 A 허용/B 거부 복구와 타 서비스·감사 보존을 확인합니다. 이 시험의 안전 사본은 시험 중 만든 가상 파일이며 실제 침해 전 검증의 증거가 아닙니다. 실제 안전 사본 복원과 공식 심판은 미실행입니다.
