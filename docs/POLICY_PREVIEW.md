# 10단계 안전 정책 비교: 읽기 전용

`npm run policy:preview`는 복원 후보 버전과 **시험 폴더를 안전 사본으로 맞출 경우의 변경 범위**만 출력합니다. 운영 API 호출·파일 쓰기·실제 복원은 없습니다.

침해 전에 정책을 검토해 안전하다고 확인한 사본을 다음 구조로 별도 보관해야 합니다. 기능은 새 사본을 만들거나 현재 파일을 자동으로 안전하다고 지정하지 않습니다.

```json
{
  "schema": "aleph.safe-policy.v1",
  "version": "안전 정책의 실제 Git 커밋 전체 40자리",
  "files": {
    "aleph.config.json": "검토한 설정 파일의 UTF-8 전체 내용",
    "src/decider.mjs": "검토한 판정기 파일의 UTF-8 전체 내용"
  }
}
```

두 파일은 필수이며 선택적으로 src/detect.mjs, src/engine-resource-grants.mjs, src/resource-policy.mjs, src/engine-resource-context.mjs를 포함할 수 있습니다. 이 목록 밖의 사용자 자료·DB·환경변수·인증 파일은 범위에 넣을 수 없습니다. 이것은 전체 자료실 백업이나 데이터 복원이 아닙니다.

검토 당시 확정한 사본 전체 바이트의 SHA-256과 버전은 사본과 별도로 신뢰할 수 있는 곳에 보관해야 합니다. 사본 안의 자체 해시나 실행 시 현재 사본에서 계산한 값을 검증 근거로 삼지 않습니다. 해시는 변경 여부를 확인할 뿐 안전성이나 침해 이전 시점을 증명하지 못합니다. 안전성·시점은 사전 검토 기록으로 확인해야 합니다.

```powershell
npm run policy:preview -- --backup <검증한사본.json> --sha256 <사전에보관한64자리해시> --version <확인한40자리커밋> --trial-dir <현재시험정책폴더>
```

모든 값은 실제 보관 기록으로 입력합니다. 현재 저장소에는 검증된 사본이 제공되지 않았으므로 인수 없이 실행하면 `safe_policy_verification_required`로 중단하는 것이 정상입니다. 사본 누락·변조·버전 불일치·허용 밖 파일·시험 경로 이탈도 중단합니다. 실행되지 않는 복원 옵션을 만들지 않습니다.

결과의 `restoreVersion`이 복원 후보 버전이며 `scope`는 비교 범위, `changes`는 변경되는 파일만 담습니다. 각 파일의 현재/안전 SHA-256 및 변경 줄 범위를 출력하고 정책 원문·메모·토큰·실명은 출력하지 않습니다. 변경 줄 범위는 첫 변경부터 마지막 변경까지의 범위이며 내부에 유지되는 줄이 포함될 수 있습니다. 없는 시험 파일은 add 후보로 표시합니다. `applied`는 항상 false입니다.

`node --test test/policy-preview.test.mjs`로 비교·중단·쓰기 없음·CLI 결과를 가상 파일로 검사합니다. 실제 안전 사본과 운영 복원은 아직 미제공/미실행입니다. 단계 번호 변경과 커밋은 이번 읽기 전용 기능 제작에 포함하지 않습니다.
