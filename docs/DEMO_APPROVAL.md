# 서버 승인 데모

이 데모는 실제 메모를 사용하지 않습니다. 실제 기기 서명이나 하드웨어 신원도 확인하지 않습니다. 로그인한 사용자의 현재 페이지 접속을 서버가 별도로 승인하는 흐름을 가상 자료로 보여 줍니다. 설치 표시나 요청 버튼은 접근 권한을 만들지 않습니다.

## 배포 준비

1. Supabase 대시보드의 **SQL Editor → New query**에서 `docs/DEMO_APPROVAL.sql` 전체를 한 번 실행합니다. 새로운 데모 테이블만 만들며 기존 `notes` 테이블은 변경하지 않습니다. 브라우저용 역할의 직접 접근 권한은 차단합니다.
2. Supabase **Authentication → Users**에서 관리자로 사용할 계정의 User UID를 확인합니다. Vercel 프로젝트 **Settings → Environment Variables**에 `DEMO_APPROVAL_ADMIN_IDS`를 추가하고 그 UID를 값으로 설정합니다. 여러 관리자는 쉼표로 구분합니다. 서버는 브라우저의 역할·승인 값을 신뢰하지 않습니다.
3. 기존 `SUPABASE_URL`과 `SUPABASE_SECRET_KEY` 서버 설정을 사용합니다. 키를 코드나 공개 화면에 복사하지 않습니다. 환경변수 변경 후 새로 배포합니다.
4. 운영 사이트의 `/demo-approval.html`을 엽니다. 기존 자료실 첫 화면에도 데모 링크가 있습니다.

현재 연결된 Supabase 관리 도구가 없어 테이블 생성·환경변수 등록·실제 배포는 이 구현에서 실행하지 않았습니다. 관리자 UID 설정이 없으면 로그인 뒤 관리자 설정 미준비 안내가 나오고, 테이블 연결이 없으면 저장소 연결 미준비 안내가 나옵니다. 요청을 성공한 것으로 표시하지 않습니다.

## 체험 순서

1. 데모 화면에 학생 계정으로 로그인하고 **기기 승인 요청**을 누릅니다. 서버가 `pending`만 저장하고 가상 자료는 보이지 않습니다. 같은 페이지에서 다시 요청해도 자동 승인되지 않습니다.
2. 별도 창에서 관리자 계정으로 같은 데모 화면에 로그인합니다. **관리자 승인 목록 확인**에서 학생 화면에 표시된 요청 번호를 찾아 **관리자 승인**을 누릅니다. 관리자 계정 하나로 두 역할을 체험할 수도 있지만, 요청 버튼과 관리자 승인 버튼은 별개의 동작입니다.
3. 학생 화면에서 **승인 결과 확인**을 누릅니다. 서버 상태가 `approved`일 때 가상 메모가 열립니다. 자료 API도 상태를 재검사합니다.
4. 관리자가 **승인 취소**를 누르면 다음 조회와 자료 요청은 차단됩니다. 이미 화면에 표시된 자료는 학생이 다시 결과를 확인할 때 지워집니다. 설치 이벤트는 승인 상태를 바꾸지 않습니다.
5. 새로고침·새 탭·로그아웃 뒤에는 새 승인 요청이 필요합니다. 접속 핸들과 로그인 토큰은 페이지 메모리에만 있으며 localStorage/sessionStorage/IndexedDB에 넣지 않습니다. 계정당 활성 데모 요청은 하나입니다. 새 페이지의 요청은 이전 페이지 요청을 대체합니다.

## 데모 전용 API 계약

모든 요청은 기존 Supabase 학생 로그인을 서버에서 검증합니다. 모든 응답에 `demo: true`가 포함됩니다. 브라우저가 보낸 `approved`, `role`, `deviceRegistered` 필드는 거부됩니다.

| 요청 | 동작 |
|---|---|
| `POST /api/demo-device`, `{action: 'request'}` | 서버가 접속 핸들을 생성하고 해시만 DB에 저장합니다. `pending`, `requestId`, 최초 요청의 `sessionToken`을 반환합니다. 핸들은 현재 페이지 메모리에서만 보관합니다. |
| `GET /api/demo-device` | 현재 로그인과 `X-Demo-Session` 핸들에 묶인 `unregistered/pending/approved/revoked` 상태를 조회합니다. |
| `POST /api/demo-device`, `{action: 'list'}` | 서버 관리자 목록에 있는 계정만 요청 번호·상태·생성 시각을 조회합니다. 사용자 로그인 토큰이나 접속 핸들은 반환하지 않습니다. |
| `POST /api/demo-device`, `{action: 'approve', requestId}` | 관리자만 현재 대기 요청을 승인합니다. 오래된 요청 번호나 이미 처리된 요청은 409로 거부합니다. |
| `POST /api/demo-device`, `{action: 'revoke', requestId}` | 관리자만 현재 요청을 취소합니다. |
| `GET /api/demo-notes` | 현재 로그인과 핸들의 서버 기록이 `approved`인 경우에만 고정 가상 자료를 반환합니다. |

다른 계정의 핸들은 사용할 수 없고, 설치 헤더나 본문의 상태 값으로는 승인할 수 없습니다. 저장소 오류는 503으로 차단합니다. 기존 `/api/notes`, `/api/notices`, 복구 API, 판정기 규칙 및 실제 기기 승인 API에는 데모 승인을 적용하지 않습니다. 이 계약은 데모 전용이며 운영 엔진 계약이나 심판 통과 증거가 아닙니다.

검사: `node --test test/demo-approval.test.mjs test/demo-device-client.test.mjs`.
